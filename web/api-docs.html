IronLog API

Read-only access for other systems: ERP, Power BI, client portals. Keys are created by an IronLog administrator under Admin → API keys.

How to connect

  1. Ask an IronLog administrator for a key. It starts with ilk_ and is shown only once.
  2. Send it with every request: Authorization: Bearer ilk_… (or the header X-API-Key: ilk_…).
  3. Choose the site with X-Site-Code: main. A key limited to some sites uses its first site when none is given.
  4. Every answer is JSON. Money is US dollars, dates are YYYY-MM-DD, hours are machine hours.

      
Limits and errors

      
    
        
  • Keys only read (GET). They can never change records or reach settings, users or admin screens.
    • 
        
  • 300 requests a minute per key.
    • 
        
  • 401: no key, or the key is unknown, cancelled or past its end date. 403: the key may not read this address, this site, or the licence does not include API access. 429: too many requests this minute.

Webhooks: IronLog tells your system when something happens

      
An IronLog administrator adds your address under Admin → Webhooks and chooses the events. IronLog then sends an HTTPS POST with a JSON body for each event, usually within a minute.

Check it really came from IronLog

      
Work out an HMAC-SHA256 of <t>.<body> with the webhook's secret (whsec_…, given once by the administrator) and compare it with v1. Refuse messages whose t is more than 5 minutes old.

      
// Node.js
const crypto = require("crypto");
function fromIronLog(rawBody, header, secret) {
  const [, t, v1] = header.match(/^t=(\d+),v1=([0-9a-f]{64})$/) || [];
  if (!t || Math.abs(Date.now() / 1000 - Number(t)) > 300) return false;
  const expected = crypto.createHmac("sha256", secret).update(`${t}.${rawBody}`).digest("hex");
  return crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(v1));
}

      
Answer and retries

      
    
        
  • Answer with any 2xx status within 10 seconds. Do slow work afterwards.
    • 
        
  • Anything else (or no answer) is tried again after 1 minute, 5 minutes, 30 minutes, 2 hours, 6 hours and 12 hours, then marked failed. The administrator can send it again from the Messages list.
    • 
        
  • Redirects are not followed: give the final address.
    • 
        
  • A message can arrive more than once; use X-IronLog-Delivery to ignore repeats.
